Your one-day study plan

You can't deeply revise everything in one day, and you don't need to. Follow this order. The 🔥 sections are non-negotiable — everything else is a bonus if you have time left.

Morning
Self introduction (all 3 versions, out loud, 10 times). HR Questions. DevOps basics. Linux. Git & GitHub.
Afternoon
Docker (your strong area — go deep here). Jenkins. AWS basics. Then the full CI/CD pipeline answer — say it out loud until it's smooth.
Evening
Troubleshooting scenarios. Your project questions. English survival lines — memorise these, they save you when you freeze.
Before bed
Quick skim of Maven, Monitoring, Terraform, Ansible — just enough to not go blank. Skim Kubernetes, SonarQube, networking, Python for 2 minutes each.
Morning of
Do NOT cram new topics. Only re-read the "Final revision sheet" at the bottom of this page and say your self-introduction out loud twice.

2 · DevOps Basics

🔥 must know
What is DevOps?
In simple words, DevOps is a combination of Development and Operations. Earlier, developers used to write the code and give it to the operations team to deploy. This caused a lot of delays. DevOps solves this by bringing both teams together. The main goal is to automate the entire software delivery process. This helps companies release software faster, with fewer errors, and less manual work. - That is my basic understanding of DevOps.
Why do we need DevOps? (What problem does it solve?)
Before DevOps, developers used to write the code and give it to the operations team to deploy. If the code failed on the server, developers blamed the server, and operations blamed the code. DevOps removes this wall between them by sharing the responsibility and automating the manual work. - That is why we need DevOps.
What are the main stages of the DevOps Lifecycle?
The DevOps lifecycle is an endless, continuous loop. It includes Continuous Development (writing code), Continuous Integration (building code), Continuous Testing (finding bugs), Continuous Deployment (pushing to servers), and Continuous Monitoring (checking server health). - That covers the DevOps lifecycle.
What is the difference between Agile and DevOps?
Agile is a methodology used mainly by the Development team to plan and write software quickly in small steps. DevOps takes it a step further by including the Operations team to automatically test and deploy that software directly to the servers. - That is the difference between them.
What is the main role of a DevOps Engineer?
The main goal of a DevOps engineer is to automate everything. Instead of doing manual work, we build CI/CD pipelines. So, whenever a developer writes code, it gets automatically tested and safely deployed to the live servers without any human errors. - That is the main role of a DevOps engineer.
What is the difference between Continuous Delivery and Continuous Deployment?
In Continuous Delivery, the code is tested automatically, but a human must manually click a button to approve and deploy it to live servers. In Continuous Deployment, there is no human touch; if the code passes all tests, it is automatically pushed to the live servers immediately. - That is the main difference.
What is Infrastructure as Code (IaC) in DevOps?
IaC means managing and creating our cloud servers using simple code instead of manually clicking buttons on a website. Tools like Terraform and Ansible help us do this. If we need to build 100 servers, we just run the code, and it builds them exactly the same way every time without errors. - That is Infrastructure as Code.
What is the difference between Monolithic and Microservices architecture?
In a Monolithic architecture, the entire application is built as one single, large block. If one part fails, the whole app crashes. In Microservices, the app is broken down into small, independent parts. DevOps prefers Microservices because they are much easier to update and scale without affecting the rest of the app. - That is the difference between them.
What is Automation in DevOps?
Automation means using tools to perform repetitive tasks automatically without human manual effort. In DevOps, we automate everything from testing the code, building the servers, to deploying the application. This saves a lot of time and completely removes human errors. - That is what automation is.
What are the main benefits of using DevOps?
The main benefits are faster software delivery to the customers and highly stable server environments. It also saves a lot of time by automating repetitive manual tasks, and it helps teams recover very quickly if a server crashes. - Those are the main benefits of DevOps.

3 · Linux

🔥 must know
What is Linux?
Technically, Linux is a kernel. It acts as a bridge between the user and the computer hardware. When we run commands, it translates them into a language the computer understands and gives the result back to us. In DevOps, we use it because it is highly secure and stable for our servers. - That is what Linux is.
What is a Server?
A server is simply a powerful computer that runs 24 hours a day to provide services. For example, it stores the application code and databases so users can access the website anytime over the internet without any interruption. - That is a basic server.
What is the difference between Linux and Windows?
Windows has a graphical interface and is mostly used for personal computers. Linux is mostly command-line based and is widely used for servers. Companies prefer Linux because it is faster, secure, and free to use. - That is the main difference.
What are some Linux commands you use daily?
I regularly use basic commands to navigate and check files. For example, I use 'ls' to list files, 'cd' to change directories, 'mkdir' to create folders, and 'cat' to view the contents of a file. I also use 'grep' to search for specific words inside logs. - Those are my most used commands.
What is the use of the 'sudo' command?
In Linux, regular users cannot perform admin tasks, like installing software or changing system files. If we need admin rights temporarily, we add 'sudo' before the command. It gives us superuser access for that specific task. - That covers the sudo command.
How do you check and change file permissions?
We use the 'ls -l' command to check who can read, write, or execute a file. If we want to change these permissions, we use the 'chmod' command. For example, 'chmod 777' gives full permissions to everyone. - That is how we handle permissions.
How do you check running processes on a server?
If a server is slow, we need to see which application is using too much CPU or memory. We use the 'top' command to see a live list of all running processes. We can also use the 'ps' command to check specific processes. - That is how we monitor processes.
What is a package manager in Linux?
A package manager is a tool that helps us easily install, update, or remove software. For example, in Ubuntu we use 'apt', and in RedHat we use 'yum'. It automatically downloads the software and sets it up. - That is the role of a package manager.
How do you check if your server is connected to the internet?
We use the 'ping' command followed by a website name, like 'ping google.com'. If the server is connected, it will receive a response back. If it fails, it means there is a network issue. - That is how we check connectivity.
How do you check logs in Linux?
Logs are very important to find out why an application or server failed. To check live logs, I use the 'tail -f' command, which shows the new lines as they are happening. If I need to find a specific error in a large file, I use the 'grep' command to search for it. - That is how I check logs.

4 · Git & GitHub

🔥 must know
What is Git?
Git is a version control system used to track changes in code. When multiple developers work on a project, Git helps them work together without deleting each other's files. It keeps a history of who made what change and when. - That is all about Git.
What is the difference between Git and GitHub?
Git is the command-line tool we install on our laptop to track code changes locally. GitHub is an online platform where we can store and share our Git repositories with other team members. - That is the main difference.
What is a repository (repo) in Git?
A repository is like a main folder for a project. It contains all the project files, sub-folders, and the complete history of all the changes made to those files since the beginning. - That covers the repository.
What is a branch in Git?
A branch is like a separate, safe workspace. If a developer wants to work on a new feature, they create a new branch so they don't disturb the main working code. Once tested, it is merged back. - That is the use of a branch.
What is a commit in Git?
A commit is like saving a checkpoint of your work. When we make changes to a file and commit it, Git permanently saves that specific version along with a small message explaining what we changed. - That is what a commit means.
What is the standard Git workflow to push code?
First, we use 'git add' to select the modified files. Next, we use 'git commit' to save those changes locally with a message. Finally, we use 'git push' to upload the code from our laptop to GitHub. - That is the standard Git workflow.
What is the difference between 'git fetch' and 'git pull'?
'git fetch' simply checks GitHub for any new changes but does not mix them with our local code. 'git pull' downloads the new changes and immediately merges them into our current working files. - That is the difference between them.
What is a merge conflict?
A merge conflict happens when two developers change the exact same line in the same file. Git gets confused about which change to keep, so a developer has to manually check and fix the file before merging. - That is a merge conflict.
How do you download code from GitHub to your laptop?
We use the 'git clone' command followed by the repository URL. This downloads a full copy of the remote GitHub project onto our local machine, including all its branches and history. - That is how we clone a repo.
What is a Pull Request (PR) in GitHub?
A Pull Request is a request to merge your new code into the main branch. It allows other team members to review your code, discuss changes, and approve it before the code actually goes to the main branch. - That is the purpose of a PR.

5 · Docker

🔥 must know
What is Docker?
Docker is a tool used to containerize applications. Sometimes an app works on a developer's laptop but fails on the server. Docker fixes this by packing the app and all its requirements into a single box called a container. This ensures the application runs exactly the same way anywhere. - That covers Docker.
What is the difference between a Virtual Machine (VM) and a Container?
A Virtual Machine needs its own full operating system to run, which makes it heavy and slow. A Docker container shares the host's operating system, making it very lightweight and fast to start. - That is the main difference.
What is a Docker Image?
A Docker Image is like a read-only template or a blueprint. It contains the application code, libraries, and everything needed to run the application, but it is not running yet. - That covers Docker Image.
What is a Docker Container?
A container is the running instance of a Docker Image. When we execute a Docker Image, it becomes a live container and starts running the application inside it. - That is a Docker Container.
What is a Dockerfile?
A Dockerfile is a simple text file with a set of instructions. It tells Docker how to build a Docker Image step by step, like what base OS to use and what files to copy. - That is the use of a Dockerfile.
What is Docker Hub?
Docker Hub is an online cloud storage, just like GitHub but for Docker Images. We can download ready-made images from it, like Ubuntu or MySQL, or upload our own custom images to share with others. - That is Docker Hub.
How do you build an image from a Dockerfile?
We use the 'docker build' command. We go to the folder where the Dockerfile is located and run this command. Docker reads the instructions in the file and creates the image. - That is how we build an image.
What are some basic Docker commands you use daily?
I use 'docker images' to see the list of images, and 'docker ps' to check running containers. To start a new container, I use 'docker run', and to stop it, I use 'docker stop'. - Those are my regular Docker commands.
What is a Docker Volume?
Normally, when a container gets deleted, all the data inside it is also lost. To prevent this, we use Docker Volumes. It safely saves the container's data on our main server so we don't lose it. - That is the purpose of Docker Volumes.
Can you explain the Dockerfile instructions?
- FROM: Selects the base operating system. - WORKDIR: Sets the working folder inside the container. - RUN: Installs the required software while building the image. - COPY: Simply move our files from the laptop into the image. - ADD: Similar to COPY, but it can also download files from the internet and extract compressed files automatically. - EXPOSE: Defines the network port for the application. - CMD: Runs the application, but the user can easily change or override this command. - ENTRYPOINT: Also runs the application, but it is fixed and cannot be easily changed. - That covers the Dockerfile instructions.

6 · Jenkins

🔥 must know
What is CI/CD?
CI/CD stands for Continuous Integration and Continuous Deployment. Continuous Integration (CI) is the first part. Whenever developers write new code, they merge it into a main branch. Then, automated tools instantly test that code to catch bugs early. Continuous Deployment (CD) is the next step. It takes that tested code and automatically pushes it to the servers. In short, it is an automated pipeline that moves code from a developer's laptop to the live environment safely and quickly. - So, that's CI/CD in short.
What is Jenkins?
Jenkins is a popular open-source tool used for automation. Its main job is to run CI/CD pipelines. Whenever a developer pushes code to Git, Jenkins automatically picks it up, builds it, and tests it to find errors. Basically, it works like a robot that removes manual work and saves a lot of time for the team. - That is the main role of Jenkins.
What is a Jenkinsfile?
A Jenkinsfile is a simple text file where we define our entire CI/CD pipeline. Instead of creating jobs manually in the Jenkins UI, we write steps like build, test, and deploy as code. It is then stored in the Git repository along with the actual application code. - That is what we call Pipeline-as-Code in Jenkins.
What is the difference between Declarative and Scripted pipelines?
There are two ways to write a Jenkinsfile. Scripted is the older way, which uses complex programming logic. Declarative is the newer and easier way, which uses a very simple and readable structure. We mostly use Declarative pipelines today. - That is the difference between them.
What are Jenkins Plugins?
Jenkins alone cannot do everything on its own. Plugins are small add-ons that give extra features to Jenkins. For example, if we want Jenkins to connect to Git, Docker, or SonarQube, we just install their specific plugins. - That is the use of plugins.
What is a Jenkins Workspace?
A workspace is simply a temporary folder created by Jenkins on the server. When a pipeline runs, Jenkins downloads the code from Git into this folder, does all the building and testing here, and moves forward. - That is a Jenkins workspace.
How does Jenkins automatically know when new code is pushed to Git?
We use a feature called Webhooks. We configure a webhook in GitHub. So, the moment a developer pushes new code, GitHub automatically sends a signal to Jenkins, and Jenkins immediately starts the pipeline. - That is how Webhooks work.
What is a Jenkins Agent (or Slave node)?
If we run hundreds of jobs on the main Jenkins server (Master), it will become slow or crash. To avoid this, we connect extra servers to Jenkins, called Agents. The Master just gives the orders, and these Agents do the actual heavy work of building the code. - That is the Jenkins Agent concept.
How do you troubleshoot a failed pipeline in Jenkins?
If a pipeline fails, the first thing I do is check the console logs in Jenkins. The logs clearly show exactly which step failed and give the error message. Based on that error, I investigate further or inform the development team. - That is my troubleshooting approach.

7 · AWS

🔥 must know
What is AWS?
AWS stands for Amazon Web Services. It is a cloud computing platform that provides resources like servers, storage, and databases over the internet. Instead of buying physical hardware, we just rent it on a pay-as-you-go basis. - That is what AWS is.
What is an EC2 instance?
EC2 stands for Elastic Compute Cloud. It is simply a virtual server in the AWS cloud. We can choose our required CPU, RAM, and operating system (like Linux or Windows) to run our applications on it. - That covers EC2.
What is Amazon S3?
S3 stands for Simple Storage Service. It is an unlimited cloud storage service where we can safely store and retrieve any amount of data, like images, logs, and backups. We store these files in folders called "Buckets". - That is what S3 is.
What is IAM in AWS?
IAM stands for Identity and Access Management. It is a security service used to create users, groups, and roles. It helps us control exactly who can access which AWS resources and what actions they can perform. - That is the main role of IAM.
What is the difference between an IAM Role and an IAM Policy?
An IAM Policy is a JSON document that defines exact permissions, like "allow read access to S3". An IAM Role is an identity that we attach to AWS resources (like EC2 instances), not to human users. The Role uses the Policy to get the permissions it needs. - That is the difference between them.
What is a VPC?
VPC stands for Virtual Private Cloud. It allows us to create our own isolated, private network inside the AWS public cloud. We place our databases and main servers inside this VPC so hackers on the internet cannot reach them directly. - That covers VPC.
What is a Security Group?
A Security Group acts as a virtual firewall for our EC2 instances. It controls the network traffic going in and coming out of our server. For example, we open port 22 for SSH access and port 80 for web traffic using security group rules. - That is the purpose of a Security Group.
What is an Auto Scaling Group?
Auto Scaling automatically monitors our application load. If the user traffic suddenly increases, it automatically adds more EC2 servers to handle the load. When the traffic drops, it automatically removes the extra servers to save costs. - That is how Auto Scaling works.
What is an Elastic Load Balancer (ELB)?
When multiple EC2 instances are running, a Load Balancer sits in front of them. It receives all the incoming user traffic and distributes it equally among the active instances so that no single server is overloaded or crashes. - That is the use of a Load Balancer.
What is Amazon Route 53?
Route 53 is the DNS (Domain Name System) service of AWS. Its main job is to act like a phonebook. It connects user-friendly website names (like mywebsite.com) to the actual IP addresses of our Load Balancers or EC2 servers. - That is Route 53.

8 · Terraform

⭐ should know
What is Terraform?
Terraform is an Infrastructure as Code tool. Instead of manually logging into a cloud provider to create servers, we write simple code to create them. If we need the exact same setup again, we just run the code. - That is how Terraform works.
Can you explain the standard Terraform workflow?
The daily workflow uses three main commands. First, we run 'terraform init' to download the required plugins. Then, we run 'terraform plan' to see a preview of what will be created. Finally, we run 'terraform apply' to actually create those resources in the cloud. - That is the standard workflow.
What is a Terraform Provider?
Terraform can work with many platforms like AWS, Azure, or Kubernetes. A provider is like a plugin that helps Terraform understand and connect to a specific cloud platform's API to create those resources. - That is the role of a provider.
What is the Terraform State file?
When Terraform creates resources, it needs to remember what it created. It stores all this information in a file called 'terraform.tfstate'. It acts as a database mapping our written code to the actual real cloud resources. - That covers the state file.
Why do we need a Remote Backend?
By default, the state file is saved locally on our laptop. If a team of developers is working together, everyone needs access to the same state file. So, we store it remotely in a central place, like an AWS S3 bucket, to share it securely. - That is why we use a remote backend.
What is State Locking in Terraform?
If two developers run 'terraform apply' at the exact same time, the state file can get corrupted. State locking prevents this by locking the file when one person is using it, making the second person wait. We usually use AWS DynamoDB for this. - That is the purpose of state locking.
What are Terraform Modules?
Modules are like reusable folders of Terraform code. If we need to create the same type of server for different environments (like Dev, QA, and Prod), we don't write the code 3 times. We just create one module and reuse it to save time. - That is the use of modules.
How do you pass inputs to your Terraform code?
We use Variables. Instead of hardcoding values like server names or instance types directly in the main code, we define them in a 'variables.tf' file. This makes our code very flexible and easy to change. - That is how we use variables.
What is the 'terraform destroy' command?
This command is used to permanently delete the infrastructure. It reads the state file, finds every resource that Terraform created, and cleanly removes them from the cloud platform. We mostly use this in testing environments to save costs. - That is how we use the destroy command.

9 · Ansible

⭐ should know
What is Ansible?
Ansible is a configuration management tool. If I need to install a software on a hundred servers, doing it manually takes hours. With Ansible, I can write a simple playbook and update all servers at the exact same time. - That is it for Ansible.
What is the main advantage of Ansible?
The biggest advantage is that Ansible is "agentless". Unlike other tools, we do not need to install any special software or agents on the target servers. It simply connects to them using basic SSH and does the work. - That is its main advantage.
What is an Ansible Inventory?
An inventory is simply a text file where we list the IP addresses of all our target servers. We can also group these servers, like putting all web servers in one group and database servers in another, to manage them easily. - That covers the inventory.
What is an Ansible Playbook?
A playbook is a YAML file where we write our actual automation code. It contains a list of tasks, like installing packages, starting services, or copying files, which we want to execute on our target servers. - That is an Ansible playbook.
What are Ansible Modules?
Modules are the actual tools that do the work in Ansible. When we write a task in a playbook, we use a specific module. For example, we use the 'yum' or 'apt' module to install software, and the 'copy' module to transfer files. - That is the use of modules.
What does Idempotency mean in Ansible?
Idempotency is a very important concept. It means no matter how many times you run an Ansible playbook, it will only make changes if they are actually needed. If the server is already correctly configured, it will do nothing. - That is what idempotency means.
What is an Ansible Role?
When a playbook becomes too big, it is very hard to read and manage. Roles help us break down that big playbook into smaller, organized folders like tasks, variables, and files. This makes the code clean and easy to reuse. - That is the purpose of roles.
What are Ad-hoc commands in Ansible?
Playbooks are used for full setups. But if we want to do a quick task, like checking the uptime of 50 servers immediately, we run a single line command in the terminal instead of writing a full playbook. - That covers ad-hoc commands.
How does Ansible connect to Linux servers securely?
Ansible uses standard SSH keys for connection. We generate an SSH key on our main Ansible server and copy the public key to all the target servers. After that, Ansible can connect and run tasks without asking for a password. - That is how the connection works.

10 · Monitoring

⭐ should know
Why do we need Monitoring in DevOps?
We need monitoring to constantly check the health of our servers and applications. If a server's CPU goes to 100% or an application crashes, monitoring tools immediately send us an alert so we can fix it quickly. - That is the main purpose of monitoring.
What is Prometheus?
Prometheus is an open-source monitoring tool. Its main job is to collect numerical data, called "metrics", from our servers. Examples of metrics are CPU usage, memory usage, and hard disk space. - That is what Prometheus is.
How does Prometheus collect data?
Prometheus uses a "Pull" mechanism. Instead of waiting for the servers to push their data, Prometheus actively connects to the target servers at regular intervals (like every 15 seconds) and pulls the data itself. - That is how it collects data.
What is Node Exporter?
Node Exporter is a small software we install on our Linux servers. Prometheus cannot understand the server directly. So, Node Exporter reads the server's CPU and memory data, and translates it into a format that Prometheus can understand and pull. - That covers Node Exporter.
What is Grafana?
Grafana is an open-source visualization tool. Prometheus collects the raw data, but raw numbers are hard to read. Grafana connects to Prometheus and converts that raw data into beautiful, easy-to-understand graphs and dashboards. - That is the role of Grafana.
What is the relationship between Prometheus and Grafana?
They work perfectly together like a backend and frontend. Prometheus is the backend database that silently collects and stores the server metrics. Grafana is the frontend screen that displays those metrics as charts. - That is their relationship.
What is PromQL?
PromQL stands for Prometheus Query Language. It is a simple language we use to search, filter, and calculate the metrics stored inside Prometheus, just like we use SQL to search in normal databases. - That is what PromQL is.
What is Loki?
Loki is a log aggregation tool. Instead of manually logging into 10 different servers to check error logs, Loki collects all the text logs from every server and stores them in one central place. - That is what Loki is.
What is the difference between Prometheus and Loki?
The difference is very simple. Prometheus is used only for "Metrics" (numbers, like CPU 80%). Loki is used only for "Logs" (text messages, like 'Error 404' or 'Database connection failed'). Both can be connected to Grafana. - That is the main difference between them.
How do you get alerts if a server goes down?
We use a tool called Alertmanager. If a server goes down, Prometheus detects it and sends a signal to Alertmanager. Alertmanager then immediately sends an automated email or a Slack message to the DevOps team. - That is how alerting works.

11 · Kubernetes

🟢 basic only
What is Kubernetes?
Kubernetes is an orchestration tool used to manage containers. While Docker is used to create containers, managing hundreds of them manually is very difficult. Kubernetes automatically handles scaling, restarting, and managing these containers. - That is Kubernetes in short.
What is the difference between Docker and Kubernetes?
Docker is used to build and run single containers. But if we have hundreds of containers, managing them manually is very difficult. Kubernetes is the tool that automatically manages, scales, and monitors all those Docker containers. - That is the main difference.
What is a Pod in Kubernetes?
A Pod is the smallest and most basic unit in Kubernetes. In Kubernetes, we do not run containers directly. Instead, we put the container inside a Pod, and Kubernetes manages that Pod. Usually, one Pod contains one container. - That covers the Pod concept.
What is a Node in Kubernetes?
A Node is simply a physical server or a virtual machine in our Kubernetes cluster. There are two types: Master nodes that control and manage everything, and Worker nodes where our actual application Pods are running. - That is what a Node is.
What is a Deployment in Kubernetes?
A Deployment is a resource used to manage our Pods. If a Pod crashes, the Deployment automatically creates a new one to replace it. It also helps us easily upgrade our application to a new version without any downtime. - That is the purpose of a Deployment.
What is a Kubernetes Service?
Pods are born and die constantly, and their IP addresses keep changing. A Service acts as a load balancer and gives a permanent IP address to a group of Pods. This allows users to access our application constantly without worrying about changing IPs. - That is the role of a Service.
What is a ReplicaSet?
A ReplicaSet ensures that a specific number of Pods are always running. For example, if we configure it to keep 3 Pods running, and one suddenly crashes, the ReplicaSet immediately starts a new one to maintain the count of 3. - That is how a ReplicaSet works.
What is a Namespace?
A Namespace is like a virtual cluster inside our main Kubernetes cluster. If multiple teams (like Dev, QA, Prod) are using the same cluster, we create separate namespaces for them so their resources do not mix or disturb each other. - That covers Namespaces.
What is 'kubectl'?
'kubectl' is the command-line tool we use to talk to the Kubernetes cluster. Just like we use Docker commands, we use 'kubectl' commands to create resources, check Pod status, view logs, and manage the entire cluster from our laptop. - That is the use of kubectl.
How do you manage configurations and passwords in Kubernetes?
We use ConfigMaps and Secrets. We use ConfigMaps to store plain text configurations, like database URLs. For sensitive data, like passwords and API keys, we safely store them using Secrets. - That is how we manage them.

12 · SonarQube

🟢 basic only
What is SonarQube?
SonarQube is an automated code quality testing tool. Think of it like a grammar checker, but for programming code. It automatically scans the developer's code to find hidden errors and security issues before the app goes live. - That is what SonarQube is.
What exactly does SonarQube check? (Bugs, Vulnerabilities, Code Smells)
It mainly checks three things. First is a Bug, which is an error that will crash the app. Second is a Vulnerability, which is a security hole that hackers can use. Third is a Code Smell, which is not an error, but confusing code that is hard to read and maintain later. - Those are the main things it checks.
What is a Quality Gate?
A Quality Gate is just a strict pass or fail rule. We can set a rule like "the code must have zero bugs". If the code meets this rule, the gate says "Passed". If it doesn't, the gate says "Failed" and stops the code from moving forward. - That is the purpose of a Quality Gate.
What is a Quality Profile?
A Quality Profile is simply a collection of rules for a specific language. For example, Java will have its own set of rules, and Python will have a different set. SonarQube uses this profile to check if the developer followed the correct coding standards for that language. - That covers Quality Profiles.
How does SonarQube work with Jenkins?
We put SonarQube right inside our CI/CD pipeline. After Jenkins builds the code, it runs the Sonar scan. If the Quality Gate fails, Jenkins automatically stops the pipeline, prevents the deployment, and sends an alert to the developers. - That is how they work together.
What is Code Coverage in SonarQube?
Code coverage simply tells us how much of the code is actually being tested. If the coverage is 80%, it means the developers wrote test cases for 80% of their code. The remaining 20% is untested and might have hidden issues. - That is what code coverage means.
What is "Technical Debt" in SonarQube?
Technical debt is an estimate of time. Sometimes developers write messy code just to finish a task quickly. SonarQube analyzes this and tells us exactly how many hours or days it will take to clean up and fix that messy code in the future. - That is technical debt.
What is a SonarScanner?
SonarQube has two main parts: the Server and the Scanner. The SonarScanner is a small tool that runs on our Jenkins machine. It actually reads the code, analyzes it, and then sends the final report to the main SonarQube Server dashboard to display. - That is the role of SonarScanner.
What is a "False Positive" and how do you handle it?
Sometimes SonarQube flags a piece of code as a bug, but as humans, we know it is actually safe and correct. This is a false positive. In this case, an admin or senior developer can simply log into SonarQube and manually mark that issue as "Resolved" or "Safe". - That is how we handle false positives.
Why do we use SonarQube when developers already review the code manually?
Manual code reviews take a lot of time, and humans can easily miss small security flaws in thousands of lines of code. SonarQube automates this. It checks everything in a few seconds and guarantees that bad code never reaches the live servers. - That is the main benefit of SonarQube.

13 · Architecture Recap

🔥 must know
Can you explain the Docker architecture?
Docker follows a Client-Server architecture. It consists of 4 main components: - Docker Client: The CLI or terminal where users run commands (like docker build or docker run). - Docker Daemon (Server): The background service running on the host that listens to client requests and manages objects. - Images and Containers: Images are the read-only templates, and containers are the running instances of those images. - Docker Registry: The storage system (like Docker Hub) where we push and pull Docker images. - That covers the Docker architecture.
Can you explain the Git architecture?
Git follows a Distributed Version Control architecture. It consists of 4 main areas: - Working Directory: The local folder where we create and edit our files. - Staging Area: A temporary index where we add files before committing them. - Local Repository: The hidden .git folder on our laptop where our committed history is saved safely. - Remote Repository: The central server (like GitHub) where we push our code to collaborate with others. - That covers the Git architecture.
Can you explain the Jenkins architecture?
Jenkins follows a Master-Agent (or Master-Slave) distributed architecture. It consists of 3 main components: - Jenkins Master: The main server that schedules jobs, monitors the agents, and records the pipeline results. - Jenkins Agent (Node): The worker servers that actually execute the builds, run tests, and do the heavy lifting. - Webhooks / SCM: The trigger mechanism that automatically notifies the Master when new code is pushed to Git. - That covers the Jenkins architecture.
Can you explain the Terraform architecture?
Terraform follows a Plugin-based architecture. It consists of 3 main components: - Terraform Core: The main engine that reads our configuration files and creates the execution plan. - Terraform Providers: The plugins (like AWS, Azure) that allow Terraform to communicate with the actual cloud APIs. - State File (.tfstate): The database file where Terraform tracks and maps the real-world cloud resources to our code. - That covers the Terraform architecture.
Can you explain the Ansible architecture?
Ansible follows a Push-based, Agentless architecture. It consists of 4 main components: - Control Node: The main machine where Ansible is installed and where we run our commands. - Inventory: A configuration file containing the IP addresses or hostnames of all target servers. - Playbooks & Modules: Playbooks are YAML files containing tasks, and Modules are the tools that execute those tasks. - Managed Nodes: The target servers that are configured via standard SSH connection, without needing any agents. - That covers the Ansible architecture.
Can you explain a basic AWS VPC architecture?
A standard AWS VPC follows a Multi-tier network architecture. It consists of 4 main components: - VPC (Virtual Private Cloud): The main isolated, private network boundary in the AWS cloud. - Internet Gateway (IGW): The component attached to the VPC that allows communication with the outside internet. - Public Subnets: The network areas that have direct internet access (used for Load Balancers or Web Servers). - Private Subnets: The secure network areas with no direct internet access (used for backend Databases). - That covers the VPC architecture.
Can you explain the Kubernetes (K8s) architecture?
Kubernetes follows a Master-Worker cluster architecture. It consists of 4 core components: - Control Plane (Master Node): The brain of the cluster. It includes the API Server, Scheduler, and etcd database to manage everything. - Data Plane (Worker Nodes): The physical or virtual machines where our actual applications run. - Kubelet: The primary agent that runs on every worker node and communicates with the Master node. - Pods: The smallest deployable units in Kubernetes that contain one or more running containers. - That covers the Kubernetes architecture.

16 · Complete CI/CD pipeline

🔥 must know

Pipeline: Developer → GitHub → Jenkins → SonarQube → Maven → Test → Docker → Docker Registry → AWS → Monitoring. This is one of the most likely questions you'll get — practice the final answer below until it's smooth.

Explain your CI/CD pipeline. (final 30–60 second answer)
I will explain my CI/CD pipeline step by step. First, the developer writes code and pushes it to GitHub. GitHub triggers a webhook, which automatically starts a Jenkins pipeline. Jenkins pulls the latest code from GitHub. Then Jenkins runs a Maven build, to compile and package the application. After that, SonarQube checks the code quality. Then Jenkins runs the test cases, to make sure the code is working correctly. After testing, Jenkins builds a Docker image using the Dockerfile, and pushes it to the Docker Registry. Then the application is deployed on AWS, for example on an EC2 instance, by pulling the image and running it as a container. Finally, monitoring tools continuously check the application, to make sure it's running properly. This whole process is automated — every time a developer pushes code, it goes through build, test, quality check, and deployment automatically.

17 · Troubleshooting scenarios

🔥 must know

For every scenario, follow the same pattern out loud: what you'd check first → the command → the likely reason → the fix.

Docker container stopped

First I check docker ps -a to see the container status. Then I check docker logs to find the error. Based on the reason, I fix the issue and start the container again.

Jenkins build failed

I check the console output of the failed build. I find the exact error message, fix the issue — like a code error or missing dependency — then I run the build again.

EC2 server not reachable

I check if the instance is in running state. Then I check the security group rules, to see if the correct port is open. I also confirm I am using the right key and public IP.
