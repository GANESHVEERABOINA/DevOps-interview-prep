3 · DevOps basics

🔥 must know
What is DevOps?
In simple words, DevOps is a combination of Development and Operations.[cite: 1] Earlier, developers used to write the code and give it to the operations team to deploy. This caused a lot of delays. DevOps solves this by bringing both teams together.[cite: 1] The main goal is to automate the entire software delivery process. This helps companies release software faster, with fewer errors, and less manual work.[cite: 1]
Why do we use DevOps?
Before DevOps, developers used to write the code and give it to the operations team to deploy. If the code failed on the server, developers blamed the server, and operations blamed the code. DevOps removes this wall between them by sharing the responsibility and automating the manual work.[cite: 1]
What are the benefits of DevOps?
The main benefits are faster software delivery to the customers and highly stable server environments. It also saves a lot of time by automating repetitive manual tasks, and it helps teams recover very quickly if a server crashes.[cite: 1]
What is CI/CD?
CI/CD stands for Continuous Integration and Continuous Deployment.[cite: 1] Continuous Integration (CI) is the first part. Whenever developers write new code, they merge it into a main branch. Then, automated tools instantly test that code to catch bugs early.[cite: 1] Continuous Deployment (CD) is the next step. It takes that tested code and automatically pushes it to the servers.[cite: 1]
What is Continuous Integration?
Continuous Integration means developers push code changes frequently, and every time, the code is automatically built and tested. This helps us find bugs early.
What is Continuous Delivery?
In Continuous Delivery, the code is tested automatically, but a human must manually click a button to approve and deploy it to live servers.[cite: 1]
What is Continuous Deployment?
In Continuous Deployment, there is no human touch; if the code passes all tests, it is automatically pushed to the live servers immediately.[cite: 1]
Difference between Continuous Delivery and Continuous Deployment
In Continuous Delivery, the code is tested automatically, but a human must manually click a button to approve and deploy it to live servers. In Continuous Deployment, there is no human touch; if the code passes all tests, it is automatically pushed to the live servers immediately.[cite: 1]
What is automation?
Automation means using tools to perform repetitive tasks automatically without human manual effort. In DevOps, we automate everything from testing the code, building the servers, to deploying the application. This saves a lot of time and completely removes human errors.[cite: 1]
What is a DevOps lifecycle?
The DevOps lifecycle is an endless, continuous loop. It includes Continuous Development (writing code), Continuous Integration (building code), Continuous Testing (finding bugs), Continuous Deployment (pushing to servers), and Continuous Monitoring (checking server health).[cite: 1]
What is version control?
Version control is a system that tracks changes in code over time. It helps multiple developers work together, and it helps us go back to old versions if needed. Git is a popular version control tool.
What is a CI/CD pipeline?
A CI/CD pipeline is a set of automated steps that take code from development to production. For example: code push, build, test, code quality check, create Docker image, and deploy to server.

4 · Linux

🔥 must know
What is Linux?
Technically, Linux is a kernel. It acts as a bridge between the user and the computer hardware. When we run commands, it translates them into a language the computer understands and gives the result back to us. In DevOps, we use it because it is highly secure and stable for our servers.[cite: 1]
Why is Linux used in DevOps?
Windows has a graphical interface and is mostly used for personal computers. Linux is mostly command-line based and is widely used for servers. Companies prefer Linux because it is faster, secure, and free to use.[cite: 1]
What is a file? What is a directory?
A file is a place where we store data, like text or code. A directory is a folder that contains files and other directories.
What is a Linux permission? Explain r, w, x.
We use the 'ls -l' command to check who can read, write, or execute a file. If we want to change these permissions, we use the 'chmod' command. For example, 'chmod 777' gives full permissions to everyone.[cite: 1]
Commands — one line each
chmod

Used to change file or directory permissions. Example: chmod 755 filename

chown

Used to change the owner of a file or directory.

pwd

Shows the current working directory.

ls

Lists files and directories.

cd

Changes the current directory.

mkdir

Creates a new directory.

touch

Creates a new empty file.

cp

Copies files or directories.

mv

Moves or renames files.

rm

Removes files or directories.

cat

Shows the content of a file.

grep

Searches for a word or pattern inside a file.

ps

Shows the running processes.

top

Shows live system performance, like CPU and memory usage.

How do you check running processes?
We use the 'top' command to see a live list of all running processes. We can also use the 'ps' command to check specific processes.[cite: 1]
How do you check logs in Linux?
Logs are very important to find out why an application or server failed. To check live logs, I use the 'tail -f' command, which shows the new lines as they are happening. If I need to find a specific error in a large file, I use the 'grep' command to search for it.[cite: 1]

5 · Git

🔥 must know
What is Git?
Git is a version control system used to track changes in code. When multiple developers work on a project, Git helps them work together without deleting each other's files. It keeps a history of who made what change and when.[cite: 1]
Git vs GitHub
Git is the command-line tool we install on our laptop to track code changes locally. GitHub is an online platform where we can store and share our Git repositories with other team members.[cite: 1]
What is a repository?
A repository is like a main folder for a project. It contains all the project files, sub-folders, and the complete history of all the changes made to those files since the beginning.[cite: 1]
What is a branch in Git?
A branch is like a separate, safe workspace. If a developer wants to work on a new feature, they create a new branch so they don't disturb the main working code. Once tested, it is merged back.[cite: 1]
What is a commit in Git?
A commit is like saving a checkpoint of your work. When we make changes to a file and commit it, Git permanently saves that specific version along with a small message explaining what we changed.[cite: 1]
Explain the Git workflow.
First, we use 'git add' to select the modified files. Next, we use 'git commit' to save those changes locally with a message. Finally, we use 'git push' to upload the code from our laptop to GitHub.[cite: 1]
git pull vs git fetch
'git fetch' simply checks GitHub for any new changes but does not mix them with our local code. 'git pull' downloads the new changes and immediately merges them into our current working files.[cite: 1]
What is a merge conflict?
A merge conflict happens when two developers change the exact same line in the same file. Git gets confused about which change to keep, so a developer has to manually check and fix the file before merging.[cite: 1]

6 · GitHub

🔥 must know
What is GitHub?
GitHub is an online platform where we can store and share our Git repositories with other team members.[cite: 1]
What is a Pull Request (PR) in GitHub?
A Pull Request is a request to merge your new code into the main branch. It allows other team members to review your code, discuss changes, and approve it before the code actually goes to the main branch.[cite: 1]

7 · Docker

🔥 must know
What is Docker?
Docker is a tool used to containerize applications. Sometimes an app works on a developer's laptop but fails on the server. Docker fixes this by packing the app and all its requirements into a single box called a container. This ensures the application runs exactly the same way anywhere.[cite: 1]
What is the difference between a Virtual Machine (VM) and a Container?
A Virtual Machine needs its own full operating system to run, which makes it heavy and slow. A Docker container shares the host's operating system, making it very lightweight and fast to start.[cite: 1]
What is Docker architecture? (full answer)
Docker follows a Client-Server architecture. It consists of 4 main components: - Docker Client: The CLI or terminal where users run commands. - Docker Daemon (Server): The background service running on the host that listens to client requests. - Images and Containers: Images are read-only templates, and containers are running instances. - Docker Registry: The storage system (like Docker Hub) where we push and pull Docker images.[cite: 1]
What is a Docker image? What is a Docker container? Image vs Container?
A Docker Image is like a read-only template or a blueprint. It contains the application code, libraries, and everything needed to run the application, but it is not running yet.[cite: 1] A container is the running instance of a Docker Image. When we execute a Docker Image, it becomes a live container and starts running the application inside it.[cite: 1]
What is a Dockerfile?
A Dockerfile is a simple text file with a set of instructions. It tells Docker how to build a Docker Image step by step, like what base OS to use and what files to copy.[cite: 1]
What is Docker Hub?
Docker Hub is an online cloud storage, just like GitHub but for Docker Images. We can download ready-made images from it, like Ubuntu or MySQL, or upload our own custom images to share with others.[cite: 1]
What is a Docker volume?
Normally, when a container gets deleted, all the data inside it is also lost. To prevent this, we use Docker Volumes. It safely saves the container's data on our main server so we don't lose it.[cite: 1]

8 · Jenkins

🔥 must know
What is Jenkins?
Jenkins is a popular open-source tool used for automation. Its main job is to run CI/CD pipelines. Whenever a developer pushes code to Git, Jenkins automatically picks it up, builds it, and tests it to find errors. Basically, it works like a robot that removes manual work and saves a lot of time for the team.[cite: 1]
What is Jenkins architecture? (full answer)
Jenkins follows a Master-Agent (or Master-Slave) distributed architecture. It consists of 3 main components: - Jenkins Master: The main server that schedules jobs, monitors the agents, and records results. - Jenkins Agent (Node): The worker servers that actually execute the builds and do the heavy lifting. - Webhooks / SCM: The trigger mechanism that automatically notifies the Master when new code is pushed to Git.[cite: 1]
Controller (Master) vs Agent
If we run hundreds of jobs on the main Jenkins server (Master), it will become slow or crash. To avoid this, we connect extra servers to Jenkins, called Agents. The Master just gives the orders, and these Agents do the actual heavy work of building the code.[cite: 1]
What is a Jenkinsfile?
A Jenkinsfile is a simple text file where we define our entire CI/CD pipeline. Instead of creating jobs manually in the Jenkins UI, we write steps like build, test, and deploy as code. It is then stored in the Git repository along with the actual application code.[cite: 1]
What are Jenkins Plugins?
Jenkins alone cannot do everything on its own. Plugins are small add-ons that give extra features to Jenkins. For example, if we want Jenkins to connect to Git, Docker, or SonarQube, we just install their specific plugins.[cite: 1]
How does Jenkins automatically know when new code is pushed to Git?
We use a feature called Webhooks. We configure a webhook in GitHub. So, the moment a developer pushes new code, GitHub automatically sends a signal to Jenkins, and Jenkins immediately starts the pipeline.[cite: 1]
How do you troubleshoot a failed Jenkins build?
If a pipeline fails, the first thing I do is check the console logs in Jenkins. The logs clearly show exactly which step failed and give the error message. Based on that error, I investigate further or inform the development team.[cite: 1]

10 · AWS

🔥 must know — basics only
What is AWS?
AWS stands for Amazon Web Services. It is a cloud computing platform that provides resources like servers, storage, and databases over the internet. Instead of buying physical hardware, we just rent it on a pay-as-you-go basis.[cite: 1]
What is EC2?
EC2 stands for Elastic Compute Cloud. It is simply a virtual server in the AWS cloud. We can choose our required CPU, RAM, and operating system (like Linux or Windows) to run our applications on it.[cite: 1]
What is Amazon S3?
S3 stands for Simple Storage Service. It is an unlimited cloud storage service where we can safely store and retrieve any amount of data, like images, logs, and backups. We store these files in folders called "Buckets".[cite: 1]
What is IAM? IAM user vs IAM role
IAM stands for Identity and Access Management. It is a security service used to create users, groups, and roles. It helps us control exactly who can access which AWS resources and what actions they can perform.[cite: 1] An IAM Policy is a JSON document that defines exact permissions. An IAM Role is an identity that we attach to AWS resources (like EC2 instances), not to human users.[cite: 1]
What is VPC?
VPC stands for Virtual Private Cloud. It allows us to create our own isolated, private network inside the AWS public cloud. We place our databases and main servers inside this VPC so hackers on the internet cannot reach them directly.[cite: 1]
What is a Security Group?
A Security Group acts as a virtual firewall for our EC2 instances. It controls the network traffic going in and coming out of our server. For example, we open port 22 for SSH access and port 80 for web traffic using security group rules.[cite: 1]

11 · Terraform

⭐ should know
What is Terraform?
Terraform is an Infrastructure as Code tool. Instead of manually logging into a cloud provider to create servers, we write simple code to create them. If we need the exact same setup again, we just run the code.[cite: 1]

A repository is like a main folder for a project. It contains all the project files, sub-folders, and the complete history of all the changes made to those files since the beginning.[cite: 1]
What is a branch in Git?
A branch is like a separate, safe workspace. If a developer wants to work on a new feature, they create a new branch so they don't disturb the main working code. Once tested, it is merged back.[cite: 1]
What is a commit in Git?
A commit is like saving a checkpoint of your work. When we make changes to a file and commit it, Git permanently saves that specific version along with a small message explaining what we changed.[cite: 1]
Explain the Git workflow.
First, we use 'git add' to select the modified files. Next, we use 'git commit' to save those changes locally with a message. Finally, we use 'git push' to upload the code from our laptop to GitHub.[cite: 1]
git pull vs git fetch
'git fetch' simply checks GitHub for any new changes but does not mix them with our local code. 'git pull' downloads the new changes and immediately merges them into our current working files.[cite: 1]
What is a merge conflict?
A merge conflict happens when two developers change the exact same line in the same file. Git gets confused about which change to keep, so a developer has to manually check and fix the file before merging.[cite: 1]

6 · GitHub

🔥 must know
What is GitHub?
GitHub is an online platform where we can store and share our Git repositories with other team members.[cite: 1]
What is a Pull Request (PR) in GitHub?
A Pull Request is a request to merge your new code into the main branch. It allows other team members to review your code, discuss changes, and approve it before the code actually goes to the main branch.[cite: 1]

7 · Docker

🔥 must know
What is Docker?
Docker is a tool used to containerize applications. Sometimes an app works on a developer's laptop but fails on the server. Docker fixes this by packing the app and all its requirements into a single box called a container. This ensures the application runs exactly the same way anywhere.[cite: 1]
What is the difference between a Virtual Machine (VM) and a Container?
A Virtual Machine needs its own full operating system to run, which makes it heavy and slow. A Docker container shares the host's operating system, making it very lightweight and fast to start.[cite: 1]
What is Docker architecture? (full answer)
Docker follows a Client-Server architecture. It consists of 4 main components: - Docker Client: The CLI or terminal where users run commands. - Docker Daemon (Server): The background service running on the host that listens to client requests. - Images and Containers: Images are read-only templates, and containers are running instances. - Docker Registry: The storage system (like Docker Hub) where we push and pull Docker images.[cite: 1]
What is a Docker image? What is a Docker container? Image vs Container?
A Docker Image is like a read-only template or a blueprint. It contains the application code, libraries, and everything needed to run the application, but it is not running yet.[cite: 1] A container is the running instance of a Docker Image. When we execute a Docker Image, it becomes a live container and starts running the application inside it.[cite: 1]
What is a Dockerfile?
A Dockerfile is a simple text file with a set of instructions. It tells Docker how to build a Docker Image step by step, like what base OS to use and what files to copy.[cite: 1]
What is Docker Hub?
Docker Hub is an online cloud storage, just like GitHub but for Docker Images. We can download ready-made images from it, like Ubuntu or MySQL, or upload our own custom images to share with others.[cite: 1]
What is a Docker volume?
Normally, when a container gets deleted, all the data inside it is also lost. To prevent this, we use Docker Volumes. It safely saves the container's data on our main server so we don't lose it.[cite: 1]

8 · Jenkins

🔥 must know
What is Jenkins?
Jenkins is a popular open-source tool used for automation. Its main job is to run CI/CD pipelines. Whenever a developer pushes code to Git, Jenkins automatically picks it up, builds it, and tests it to find errors. Basically, it works like a robot that removes manual work and saves a lot of time for the team.[cite: 1]
What is Jenkins architecture? (full answer)
Jenkins follows a Master-Agent (or Master-Slave) distributed architecture. It consists of 3 main components: - Jenkins Master: The main server that schedules jobs, monitors the agents, and records results. - Jenkins Agent (Node): The worker servers that actually execute the builds and do the heavy lifting. - Webhooks / SCM: The trigger mechanism that automatically notifies the Master when new code is pushed to Git.[cite: 1]
Controller (Master) vs Agent
If we run hundreds of jobs on the main Jenkins server (Master), it will become slow or crash. To avoid this, we connect extra servers to Jenkins, called Agents. The Master just gives the orders, and these Agents do the actual heavy work of building the code.[cite: 1]
What is a Jenkinsfile?
A Jenkinsfile is a simple text file where we define our entire CI/CD pipeline. Instead of creating jobs manually in the Jenkins UI, we write steps like build, test, and deploy as code. It is then stored in the Git repository along with the actual application code.[cite: 1]
What are Jenkins Plugins?
Jenkins alone cannot do everything on its own. Plugins are small add-ons that give extra features to Jenkins. For example, if we want Jenkins to connect to Git, Docker, or SonarQube, we just install their specific plugins.[cite: 1]
How does Jenkins automatically know when new code is pushed to Git?
We use a feature called Webhooks. We configure a webhook in GitHub. So, the moment a developer pushes new code, GitHub automatically sends a signal to Jenkins, and Jenkins immediately starts the pipeline.[cite: 1]
How do you troubleshoot a failed Jenkins build?
If a pipeline fails, the first thing I do is check the console logs in Jenkins. The logs clearly show exactly which step failed and give the error message. Based on that error, I investigate further or inform the development team.[cite: 1]

10 · AWS

🔥 must know — basics only
What is AWS?
AWS stands for Amazon Web Services. It is a cloud computing platform that provides resources like servers, storage, and databases over the internet. Instead of buying physical hardware, we just rent it on a pay-as-you-go basis.[cite: 1]
What is EC2?
EC2 stands for Elastic Compute Cloud. It is simply a virtual server in the AWS cloud. We can choose our required CPU, RAM, and operating system (like Linux or Windows) to run our applications on it.[cite: 1]
What is Amazon S3?
S3 stands for Simple Storage Service. It is an unlimited cloud storage service where we can safely store and retrieve any amount of data, like images, logs, and backups. We store these files in folders called "Buckets".[cite: 1]
What is IAM? IAM user vs IAM role
IAM stands for Identity and Access Management. It is a security service used to create users, groups, and roles. It helps us control exactly who can access which AWS resources and what actions they can perform.[cite: 1] An IAM Policy is a JSON document that defines exact permissions. An IAM Role is an identity that we attach to AWS resources (like EC2 instances), not to human users.[cite: 1]
What is VPC?
VPC stands for Virtual Private Cloud. It allows us to create our own isolated, private network inside the AWS public cloud. We place our databases and main servers inside this VPC so hackers on the internet cannot reach them directly.[cite: 1]
What is a Security Group?
A Security Group acts as a virtual firewall for our EC2 instances. It controls the network traffic going in and coming out of our server. For example, we open port 22 for SSH access and port 80 for web traffic using security group rules.[cite: 1]

11 · Terraform

⭐ should know
What is Terraform?
Terraform is an Infrastructure as Code tool. Instead of manually logging into a cloud provider to create servers, we write simple code to create them. If we need the exact same setup again, we just run the code.[cite: 1]
Terraform workflow / architecture (full answer)
Terraform follows a Plugin-based architecture. It consists of 3 main components: Terraform Core, Terraform Providers, and the State File (.tfstate).[cite: 1] The daily workflow uses three main commands. First, we run 'terraform init' to download the required plugins. Then, we run 'terraform plan' to see a preview of what will be created. Finally, we run 'terraform apply' to actually create those resources in the cloud.[cite: 1]
What is a Terraform Provider?
Terraform can work with many platforms like AWS, Azure, or Kubernetes. A provider is like a plugin that helps Terraform understand and connect to a specific cloud platform's API to create those resources.[cite: 1]
What is the Terraform State file?
When Terraform creates resources, it needs to remember what it created. It stores all this information in a file called 'terraform.tfstate'. It acts as a database mapping our written code to the actual real cloud resources.[cite: 1]

12 · Ansible

⭐ should know
What is Ansible?
Ansible is a configuration management tool. If I need to install a software on a hundred servers, doing it manually takes hours. With Ansible, I can write a simple playbook and update all servers at the exact same time.[cite: 1]
Ansible architecture (full answer)
Ansible follows a Push-based, Agentless architecture. It consists of 4 main components:[cite: 1] - Control Node: The main machine where Ansible is installed. - Inventory: A configuration file containing the IP addresses of all target servers. - Playbooks & Modules: Playbooks are YAML files containing tasks, and Modules execute those tasks. - Managed Nodes: The target servers configured via standard SSH connection, without needing any agents.[cite: 1]
What is the main advantage of Ansible?
The biggest advantage is that Ansible is "agentless". Unlike other tools, we do not need to install any special software or agents on the target servers. It simply connects to them using basic SSH and does the work.[cite: 1]

13 · Kubernetes

🟢 basic only
What is Kubernetes?
Kubernetes is an orchestration tool used to manage containers. While Docker is used to create containers, managing hundreds of them manually is very difficult. Kubernetes automatically handles scaling, restarting, and managing these containers.[cite: 1]
What is a Pod? What is a Node?
A Pod is the smallest and most basic unit in Kubernetes. In Kubernetes, we do not run containers directly. Instead, we put the container inside a Pod, and Kubernetes manages that Pod.[cite: 1] A Node is simply a physical server or a virtual machine in our Kubernetes cluster.[cite: 1]
Kubernetes architecture
Kubernetes follows a Master-Worker cluster architecture. It consists of: - Control Plane (Master Node): The brain of the cluster. - Data Plane (Worker Nodes): The physical or virtual machines where our actual applications run. - Kubelet: The primary agent on every worker node. - Pods: The smallest deployable units containing running containers.[cite: 1]

14 · Monitoring

⭐ should know
Why do we need Monitoring in DevOps?
We need monitoring to constantly check the health of our servers and applications. If a server's CPU goes to 100% or an application crashes, monitoring tools immediately send us an alert so we can fix it quickly.[cite: 1]
What is Prometheus? What is Grafana?
Prometheus is an open-source monitoring tool. Its main job is to collect numerical data, called "metrics", from our servers (like CPU usage, memory usage).[cite: 1] Grafana is an open-source visualization tool. Grafana connects to Prometheus and converts that raw data into beautiful, easy-to-understand graphs and dashboards.[cite: 1]

15 · SonarQube

🟢 basic only
What is SonarQube?
SonarQube is an automated code quality testing tool. Think of it like a grammar checker, but for programming code. It automatically scans the developer's code to find hidden errors and security issues before the app goes live.[cite: 1]
What exactly does SonarQube check?
It mainly checks three things. First is a Bug, which is an error that will crash the app. Second is a Vulnerability, which is a security hole that hackers can use. Third is a Code Smell, which is not an error, but confusing code that is hard to read and maintain later.[cite: 1]
How does SonarQube work with Jenkins?
We put SonarQube right inside our CI/CD pipeline. After Jenkins builds the code, it runs the Sonar scan. If the Quality Gate fails, Jenkins automatically stops the pipeline, prevents the deployment, and sends an alert to the developers.[cite: 1]
