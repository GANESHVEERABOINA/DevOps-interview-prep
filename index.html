3 · DevOps basics

🔥 must know
What is DevOps?
DevOps is a combination of Development and Operations. It is a culture and practice where developers and the operations team work together. The goal is to build, test, and release software faster and more reliably.
  • Dev + Ops working together
  • A culture / practice, not a tool
  • Faster, more reliable releases
Why do we use DevOps?
We use DevOps to reduce the gap between development and operations teams. It helps us release software faster, with fewer errors, and with better collaboration between teams.
What are the benefits of DevOps?
DevOps gives faster delivery, better quality, more automation, and better collaboration between teams. It also reduces manual errors and helps us fix problems quickly.
What is CI/CD?
CI/CD means Continuous Integration and Continuous Delivery or Deployment. CI means we integrate code changes frequently and test them automatically. CD means we deliver or deploy that code automatically to the next environment.
What is Continuous Integration?
Continuous Integration means developers push code changes frequently, and every time, the code is automatically built and tested. This helps us find bugs early.
What is Continuous Delivery?
Continuous Delivery means after testing, the code is automatically prepared and ready to release, but the final deployment to production is done manually, with one click.
What is Continuous Deployment?
Continuous Deployment means the tested code is automatically deployed to production, without any manual approval step.
Difference between Continuous Delivery and Continuous Deployment
In Continuous Delivery, deployment to production needs manual approval. In Continuous Deployment, there is no manual step — everything is automatic.
What is automation?
Automation means using tools and scripts to do repetitive tasks automatically, instead of doing them manually. In DevOps, we automate building, testing, and deployment.
What is a DevOps lifecycle?
The DevOps lifecycle has stages like Plan, Code, Build, Test, Release, Deploy, Operate, and Monitor. These stages repeat continuously to improve the software.
What is version control?
Version control is a system that tracks changes in code over time. It helps multiple developers work together, and it helps us go back to old versions if needed. Git is a popular version control tool.
What is a CI/CD pipeline?
A CI/CD pipeline is a set of automated steps that take code from development to production. For example: code push, build, test, code quality check, create Docker image, and deploy to server.

4 · Linux

🔥 must know

Commands don't need long explanations — say them in one short line, like the examples below.

What is Linux?
Linux is an open-source operating system. It is widely used on servers because it is stable, secure, and free.
Why is Linux used in DevOps?
Most servers and cloud machines run on Linux. A DevOps engineer needs Linux to manage servers, run scripts, and deploy applications.
What is a file? What is a directory?
A file is a place where we store data, like text or code. A directory is a folder that contains files and other directories.
What is a Linux permission? Explain r, w, x.
A permission controls who can read, write, or execute a file. r means read, w means write, and x means execute.
What are owner, group, and others?
Owner is the user who created the file. Group is a set of users who share some permission. Others means everyone else on the system.

Used to change file or directory permissions. Example: chmod 755 filename

chown

Used to change the owner of a file or directory.

pwd

Shows the current working directory.

ls

Lists files and directories.

cd

Changes the current directory.

mkdir

Creates a new directory.

touch

Creates a new empty file.

cp

Copies files or directories.

mv

Moves or renames files.

rm

Removes files or directories.

cat

Shows the content of a file.

grep

Searches for a word or pattern inside a file.

ps

Shows the running processes.

top

Shows live system performance, like CPU and memory usage.

How do you check disk usage?
I use the command df -h to check disk usage.
How do you check memory usage?
I use the command free -h to check memory usage.
How do you check running processes?
I use ps -ef, or the top command, to check running processes.
How do you find a particular process?
I use the command ps -ef, then pipe it with grep — for example: ps -ef | grep processname.
How do you change file permissions?
I use the chmod command, for example: chmod 755 filename.

5 · Git

🔥 must know
What is Git?
Git is a distributed version control tool. It helps us track changes in code and work together with other developers.
Why do we use Git?
We use Git to manage source code, track the history of changes, and collaborate with team members without overwriting each other's work.
What is a repository?
A repository is a place where our project code and its history are stored.
What is the working directory, staging area, local repository, and remote repository?
The working directory is the folder on my machine where I make changes to files. The staging area is where I keep changes that are ready to be committed. The local repository is the Git repository stored on my own machine. The remote repository is the Git repository stored on a server, like GitHub.
Commands — one line each
git init

Creates a new local Git repository.

git clone

Downloads a copy of a remote repository to the local machine.

git status

Shows the current state of files — changed, staged, or untracked.

git add

Moves changes from the working directory to the staging area.

git commit

Saves the staged changes to the local repository.

git push

Sends local commits to the remote repository.

git pull

Downloads changes from the remote repository and merges them into the local branch.

git fetch

Downloads changes from the remote repository, but does not merge them automatically.

git branch

Used to create, list, or delete branches.

git merge

Combines changes from one branch into another branch.

Why do we use branches?
Branches let us work on new features or fixes separately, without affecting the main code.
What is a merge conflict?
A merge conflict happens when Git cannot automatically combine changes, because the same part of a file was changed in two different ways. We need to fix it manually.
git pull vs git fetch
git fetch only downloads changes. git pull downloads changes and also merges them automatically.
Explain the Git workflow.
First, I make changes in the Working Directory. Then, I use git add to move changes to the Staging Area. Then, I use git commit to save changes in the Local Repository. Finally, I use git push to send changes to the Remote Repository, like GitHub.
  • Working Directory → Staging Area → Local Repository → Remote Repository

6 · GitHub

🔥 must know
What is GitHub?
GitHub is a cloud platform to host Git repositories. It helps teams store code online and collaborate.
Git vs GitHub
Git is the version control tool that runs on my machine. GitHub is an online platform where I store my Git repositories and collaborate with others.
What is a GitHub repository?
A GitHub repository is a project folder stored on GitHub, containing our code and its history.
How do you push code to GitHub? How do you clone a repository?
First I use git add and git commit locally, then I use git push to send the code to GitHub. To clone, I use git clone with the repository URL, to download it to my local machine.
How does Jenkins connect with GitHub?
Jenkins connects to GitHub using the repository URL and credentials, or using a webhook, so Jenkins can automatically pull the latest code.
What is a webhook?
A webhook is a notification that GitHub sends to Jenkins automatically, when new code is pushed. It triggers the Jenkins build automatically.
Why is GitHub used in DevOps?
GitHub is used to store code centrally, so the whole team and CI/CD tools like Jenkins can access the latest code easily.

7 · Docker

🔥 must know — your strongest area

This is where you should sound the most confident. Go slightly deeper here than other topics.

What is Docker?
Docker is a container platform. It is used to package and run applications. It helps us run applications with their required dependencies, so the application runs the same way everywhere.
Why do we use Docker?
We use Docker because it solves the problem of "it works on my machine." Docker packages the application with everything it needs, so it works the same way on any server.
What is Docker architecture? (full answer)
Docker architecture has four main parts: Docker Client, Docker Daemon, Docker Images and Containers, and Docker Registry. The Docker Client is where I type commands like docker run. The command goes to the Docker Daemon, which does the actual work. The Daemon checks if the image is available locally. If not, it pulls it from the Docker Registry, like Docker Hub. Then the Daemon creates a container from that image, and the container runs my application.
Final one-minute answer
Docker architecture has a client, a daemon, images and containers, and a registry. I type a command in the Docker Client. It goes to the Docker Daemon. The Daemon checks for the image locally, or pulls it from the Docker Registry like Docker Hub, and then creates and runs the container.
What is the Docker Client? What is the Docker Daemon?
The Docker Client is what I use to type Docker commands, like docker run or docker build. The Docker Daemon is the background service that actually creates and manages containers and images.
What is Docker Registry? What is Docker Hub?
Docker Registry is a storage place for Docker images. Docker Hub is the most common public registry, where we pull ready-made images like nginx or mysql, or push our own images.
What is a Docker image? What is a Docker container? Image vs Container?
A Docker image is a read-only template that contains the application code and everything needed to run it. A Docker container is a running instance of that image. So an image is like a blueprint, and a container is the running application created from that blueprint.
What is a Dockerfile?
A Dockerfile is a text file with instructions to build a Docker image, step by step.
What is a Docker volume? Volume vs Bind Mount?
A Docker volume is used to store data outside the container, so data is not lost when the container is removed. A volume is managed by Docker itself, and Docker decides where to store it. A bind mount points to a specific folder on my host machine instead.
What is a Docker network?
A Docker network allows containers to communicate with each other and with the outside world.
Commands — one line each
docker pull

Downloads an image from a registry.

docker run

Creates and starts a new container from an image.

docker ps

Shows the running containers.

docker ps -a

Shows all containers, running and stopped.

docker stop

Stops a running container.

docker start

Starts a stopped container.

docker restart

Stops and starts a container again.

docker rm

Removes a stopped container.

docker images

Shows all images available locally.

docker rmi

Removes an image.

docker logs

Shows the logs of a container — useful for debugging.

docker inspect

Shows detailed information about a container or image.

docker exec

Lets me run a command inside a running container, for example to open a shell.

What happens when you run "docker run nginx"?
Docker checks if the nginx image is available locally. If yes, it creates a container from that image and starts it. If not, Docker downloads it from Docker Hub first, then creates the container.
What happens if the Docker image is not available locally?
Docker automatically pulls the image from the configured registry, usually Docker Hub, and then creates the container.
How do you troubleshoot a stopped container? How do you check container logs?
First I check docker ps -a to see the container status. Then I check docker logs to see the error message. Based on the error, I fix the issue and start the container again.

8 · Jenkins

🔥 must know
What is Jenkins?
Jenkins is an open-source automation tool. It is used to automate building, testing, and deploying applications.
Why do we use Jenkins?
We use Jenkins to automate the CI/CD pipeline, so code is built, tested, and deployed automatically whenever developers push changes.
What is Jenkins architecture? (full answer)
Jenkins architecture has a Controller and one or more Agents. The Controller manages jobs, schedules builds, and shows the results in the dashboard. The Agent is the machine that actually does the work, like building and testing code. When code is pushed to GitHub, a webhook notifies Jenkins. The Controller schedules the job, sends it to an Agent, and the Agent runs the pipeline steps.
Final one-minute answer
Jenkins has a Controller and Agents. The Controller manages and schedules the jobs. The Agent actually runs the build. When a developer pushes code, GitHub sends a webhook to Jenkins, the Controller assigns the job to an Agent, and the Agent runs the pipeline — build, test, and deploy.
Controller vs Agent
The Controller (earlier called Master) manages and schedules jobs. The Agent (earlier called Slave / Node) is the machine where the actual build work happens.
What is a Jenkins job? What is a Jenkins pipeline?
A Jenkins job is a task, like building or testing a project, that Jenkins runs. A Jenkins pipeline is a set of automated steps, like build, test, and deploy, defined in a sequence.
What is a Jenkinsfile? What is a Jenkins stage?
A Jenkinsfile is a text file where I write the pipeline steps as code. A stage is one step in the pipeline, like the Build stage, Test stage, or Deploy stage.
How does Jenkins help in CI/CD?
Jenkins automates the whole pipeline. It pulls code from GitHub, builds it, runs tests, and deploys it, without manual work.
What happens when a developer pushes code to GitHub?
GitHub sends a webhook notification to Jenkins. Jenkins automatically pulls the latest code and starts the pipeline — build, test, and deploy.
How do you troubleshoot a failed Jenkins build? Where do you check logs?
First I check the Console Output of that build in Jenkins. I look for the error message, find which stage failed, and fix that issue, like a code error or a missing dependency.
Freestyle job vs Pipeline job
A freestyle job is a simple Jenkins job configured through the UI, without writing pipeline code. A pipeline job is defined using a Jenkinsfile, with code, and it's more flexible for complex CI/CD steps.

9 · Maven

⭐ should know
What is Maven? Why do we use it?
Maven is a build tool for Java projects. It helps us compile code, manage dependencies, and package the application. We use it because it automatically downloads required libraries and builds the project in a standard way.
What is pom.xml? What are dependencies?
pom.xml is the configuration file of Maven. It contains the project details and the list of dependencies. Dependencies are external libraries that our project needs to work.
What is the Maven lifecycle?
The Maven lifecycle has phases like validate, compile, test, package, and install, which run in order.
Commands — one line each
mvn clean

Removes old build files.

mvn compile

Compiles the source code.

mvn test

Runs the test cases.

mvn package

Creates the final build file, like a jar or war file.

How is Maven used in Jenkins?
In the Jenkins pipeline, we add a build stage where Jenkins calls Maven commands, like mvn clean package, to build the project.
What happens when a Maven build fails?
I check the Maven build logs in the Jenkins console output. Usually the reason is a compilation error, a missing dependency, or a failed test case. I fix that issue and run the build again.

10 · AWS

🔥 must know — basics only
What is AWS? Why do we use it?
AWS is Amazon Web Services. It is a cloud platform that provides computing, storage, and other services over the internet. We use AWS because it gives us servers and services on demand, without buying physical hardware. It is flexible and scalable.
What is cloud computing?
Cloud computing means using computing resources like servers, storage, and databases over the internet, instead of managing our own hardware.
What is EC2? What is an EC2 instance?
EC2 is Elastic Compute Cloud. It gives us virtual servers in the cloud. An EC2 instance is a single virtual server that we create using the EC2 service.
What is S3? EC2 vs S3
S3 is Simple Storage Service, used to store files and data as objects, like images, backups, or logs. EC2 gives us virtual servers to run applications. S3 is used to store files and data.
What is IAM? IAM user vs IAM role
IAM is Identity and Access Management. It controls who can access AWS resources, and what actions they can perform. An IAM user is an individual account created to access AWS resources. An IAM role is a set of permissions that can be assumed temporarily by a service or user, without sharing permanent credentials.
What is a Security Group?
A Security Group is a virtual firewall for EC2 instances. It controls incoming and outgoing traffic.
What is VPC? What is a subnet? Public vs private subnet
VPC is Virtual Private Cloud — a private network inside AWS, where we launch resources like EC2 instances. A subnet is a smaller part of a VPC network. A public subnet has direct access to the internet. A private subnet does not, which makes it more secure for internal resources.
What is SSH? How do you connect to an EC2 instance?
SSH is a secure way to connect to a remote server from my machine, using a terminal. I connect to an EC2 instance using SSH with the key pair file — for example: ssh -i keyfile.pem ec2-user@publicIP.
How do you deploy an application on EC2?
I connect to the EC2 instance using SSH, install the required software, copy or pull my application code, and run it — or run it as a Docker container.
What will you check if EC2 is not reachable?
First I check if the instance is running. Then I check the security group rules. Then I check if the correct key and public IP are being used.
What is an Availability Zone? What is a Region?
An Availability Zone is a physically separate data center within an AWS region. A Region is a geographical area, like Mumbai or Singapore, that contains multiple Availability Zones.

11 · Terraform

⭐ should know
What is Terraform? Why do we use it?
Terraform is an Infrastructure as Code tool. It helps us create and manage cloud resources using code. We use it because it lets us create infrastructure automatically and consistently, instead of creating resources manually.
What is Infrastructure as Code?
Infrastructure as Code means we write our infrastructure — servers, networks — as code files, instead of creating them manually.
Terraform workflow / architecture (full answer)
First, I write my infrastructure in Terraform files, using HCL language. Then I run terraform init, which prepares the folder and downloads the provider plugin, like the AWS provider. Then I run terraform plan, to see what changes will happen. Then I run terraform apply, to actually create the resources in AWS.
Final one-minute answer
In Terraform, I first write my infrastructure as code in Terraform files. Then I run terraform init to set up the provider. Then terraform plan to preview the changes. Then terraform apply to create the actual resources in AWS. If I want to remove everything, I run terraform destroy.
What is a provider? What is a resource?
A provider is a plugin that lets Terraform talk to a cloud platform, like AWS. A resource is the actual infrastructure item we create, like an EC2 instance or S3 bucket.
What is a variable? What is an output? What is Terraform state?
A variable lets us pass different values into our Terraform code, so it's reusable. An output shows useful information after Terraform creates resources, like the public IP of a server. Terraform state is a file that keeps track of the resources Terraform has created, so it knows what already exists.
Commands — one line each
terraform init

Prepares the working directory and downloads required provider plugins.

terraform plan

Shows what changes Terraform will make, before actually applying them.

terraform apply

Creates or updates the actual infrastructure.

terraform destroy

Removes the infrastructure created by Terraform.

Terraform vs manual resource creation
Manual creation means clicking in the AWS console each time. Terraform lets me create the same infrastructure with code, so it's faster, consistent, and repeatable.

12 · Ansible

⭐ should know
What is Ansible? Why do we use it?
Ansible is a configuration management and automation tool. It helps us install software, configure servers, and automate tasks on many servers at once. We use it because it saves time — instead of configuring servers one by one manually, we automate it using playbooks.
Ansible architecture (full answer)
The Control Node is where Ansible is installed. The Inventory file lists all the Managed Nodes. We write a Playbook with the tasks we want to perform. Ansible uses Modules to actually do the work, like installing software. The Control Node connects to Managed Nodes using SSH and runs the playbook there.
Final one-minute answer
In Ansible, the Control Node is where Ansible is installed. It reads the Inventory file to know the Managed Nodes. I write tasks in a Playbook, using Modules. Ansible connects to the Managed Nodes through SSH, and runs the playbook tasks on them, without needing any agent installed.
What is a Playbook? What is a Task? What is a Module?
A Playbook is a YAML file where I write the automation tasks, step by step. A Task is a single action in a playbook, like installing a package. A Module is a small program Ansible uses to perform that action.
What is YAML?
YAML is a simple, readable data format used to write Ansible playbooks.
How does Ansible connect to Linux servers?
Ansible connects to managed nodes using SSH, without needing an agent installed on them.
Basic Ansible commands
ansible-playbook is used to run a playbook. ansible all -m ping is used to check connectivity to all servers.
Ansible vs Terraform
Terraform is mainly used to create infrastructure, like servers. Ansible is mainly used to configure and manage software on servers that already exist.

13 · Kubernetes

🟢 basic only

Keep it simple. If they push deeper than this, it's fine to say: "I have basic knowledge of Kubernetes, I have practiced it in my learning environment, not in production."

What is Kubernetes? Why do we use it?
Kubernetes is a container orchestration tool. It helps us manage, scale, and run many containers automatically. We use it because managing many containers manually is difficult — Kubernetes automates deployment, scaling, and healing of containers.
What is a Pod? What is a Node? What is a Cluster?
A Pod is the smallest unit in Kubernetes, usually containing one or more containers. A Node is a machine, physical or virtual, where Kubernetes runs Pods. A Cluster is a group of Nodes managed together.
What is a Deployment? What is a Service? What is a ReplicaSet?
A Deployment manages how many copies of a Pod should run, and helps update them safely. A Service gives a stable way to access Pods, even if the Pods change or restart. A ReplicaSet makes sure a specific number of Pod copies are always running.
Kubernetes architecture — Control Plane and Worker Node
Kubernetes has a Control Plane, which manages the cluster, and Worker Nodes, which run the actual application Pods. The Control Plane handles scheduling and health. The Worker Node runs the Pods and reports status back.
What is self-healing? What is scaling?
Self-healing means if a Pod or container fails, Kubernetes automatically restarts or replaces it. Scaling means Kubernetes can automatically increase or decrease the number of running Pods, based on load.
Basic kubectl commands
kubectl get pods shows running pods. kubectl get nodes shows the nodes. kubectl apply -f file.yaml applies a configuration.
Docker vs Kubernetes
Docker is used to create and run containers. Kubernetes is used to manage and orchestrate many containers across multiple servers.

14 · Monitoring

⭐ should know
What is monitoring? Why do we need it?
Monitoring means continuously checking the health and performance of servers and applications. We need it to find problems early, before they affect users — like high CPU usage or application downtime.
What do we monitor? (CPU, memory, disk, network, application)
We monitor things like CPU, memory, disk, network, application logs, and uptime. CPU and memory monitoring checks resource usage, so the server doesn't run out of capacity. Disk monitoring checks storage usage, so the disk doesn't get full. Network monitoring checks traffic and connectivity between servers. Application monitoring checks if the application is running and responding properly.
What are logs? What are alerts?
Logs are records of events and errors generated by the system or application — we check logs to find the root cause of a problem. Alerts are notifications sent automatically when something goes wrong, like high CPU or the server going down.
How does monitoring help DevOps?
Monitoring helps us detect and fix issues quickly, and improve system reliability.
What will you check if CPU usage is high?
I check which process is using high CPU using the top command, and then decide if I need to restart the process or scale the server.
What will you check if disk is full?
I use df -h to check disk usage, then find and remove unnecessary files, or clean up logs.
What will you check if the application is down or slow?
If the application is down, first I check if the server is reachable, then I check the application logs and process status. If the application is slow, I check CPU and memory usage, and application logs, to see if there's a resource issue or an error.
Do you know any monitoring tools?
I have basic knowledge of monitoring tools like Prometheus, Grafana, and AWS CloudWatch. Prometheus collects and stores metrics like CPU and memory data over time. Grafana is a dashboard tool used to visualize that data. CloudWatch is AWS's built-in monitoring service, used to monitor AWS resources and set alarms. I have practiced these basics in my learning environment.

15 · SonarQube

🟢 basic only
What is SonarQube? Why do we use it?
SonarQube is a code quality tool. It checks our code for bugs, code smells, and security issues. We use it to make sure our code quality is good before it goes to production.
What does SonarQube check?
It checks things like bugs, vulnerabilities, code duplication, and coding standard violations.
How does SonarQube fit into CI/CD? How does Jenkins work with it?
After the build and test stage, SonarQube analyzes the code quality before we move to the next step, like packaging or deployment. Jenkins runs a SonarQube scan as a stage in the pipeline, and if the code quality doesn't meet the standard, the pipeline can be stopped.

Basic Networking

🟢 basic only
What is networking? What is an IP address?
Networking means connecting computers and servers together, so they can communicate and share data. An IP address is a unique number that identifies a device on a network.
What is a port? What is DNS?
A port is a number used to identify a specific service running on a server, like port 80 for websites. DNS converts a website name into an IP address, so computers can find each other.
What is a firewall? HTTP vs HTTPS
A firewall controls incoming and outgoing traffic, to protect a server from unauthorized access. HTTP is normal web traffic. HTTPS is the secure, encrypted version of HTTP.

A variable stores a value, like a number or text, so we can use it later. A list stores multiple values together, like a list of server names. A function is a block of code that performs a task, and we can reuse it. A loop repeats a task multiple times, like checking the status of multiple servers one by one.

16 · Complete CI/CD pipeline

🔥 must know

Pipeline: Developer → GitHub → Jenkins → SonarQube → Maven → Test → Docker → Docker Registry → AWS → Monitoring. This is one of the most likely questions you'll get — practice the final answer below until it's smooth.

Where does each tool fit in the pipeline?
GitHub stores the source code, and Jenkins pulls the latest code from GitHub when the pipeline starts. Jenkins is the main automation engine — it runs all the stages: build, test, code quality check, and deployment. Maven is used in the build stage, to compile the code and package it, for example into a jar file. SonarQube runs after the build stage, to check code quality before moving forward. After the build, Docker creates a container image of the application using a Dockerfile. The application is deployed on AWS, for example on an EC2 instance. After deployment, monitoring tools continuously check the application's health and performance.
Explain your CI/CD pipeline. (final 30–60 second answer)
I will explain my CI/CD pipeline step by step. First, the developer writes code and pushes it to GitHub. GitHub triggers a webhook, which automatically starts a Jenkins pipeline. Jenkins pulls the latest code from GitHub. Then Jenkins runs a Maven build, to compile and package the application. After that, SonarQube checks the code quality. Then Jenkins runs the test cases, to make sure the code is working correctly. After testing, Jenkins builds a Docker image using the Dockerfile, and pushes it to the Docker Registry. Then the application is deployed on AWS, for example on an EC2 instance, by pulling the image and running it as a container. Finally, monitoring tools continuously check the application, to make sure it's running properly. This whole process is automated — every time a developer pushes code, it goes through build, test, quality check, and deployment automatically.

17 · Architecture quick-revise

🔥 must know

The full explanations are in each tool's own section above. These are just the compressed, one-minute versions for a fast final review.

Git architecture (one-minute answer)
Git has four parts: Working Directory, Staging Area, Local Repository, and Remote Repository. I make changes in the Working Directory. I use git add to move changes to the Staging Area. I use git commit to save changes in the Local Repository. Finally, I use git push to send changes to the Remote Repository, like GitHub.
GitHub's role (one-minute answer)
GitHub stores my remote repository in the cloud. My local Git repository connects to GitHub using git push and git pull. GitHub also connects with Jenkins using a webhook, so when I push code, Jenkins is triggered automatically.
Docker architecture (one-minute answer)
Docker architecture has a client, a daemon, images and containers, and a registry. I type a command in the Docker Client. It goes to the Docker Daemon. The Daemon checks for the image locally, or pulls it from the Docker Registry like Docker Hub, and then creates and runs the container.
Jenkins architecture (one-minute answer)
Jenkins has a Controller and Agents. The Controller manages and schedules the jobs. The Agent actually runs the build. When a developer pushes code, GitHub sends a webhook to Jenkins, the Controller assigns the job to an Agent, and the Agent runs the pipeline — build, test, and deploy.
Terraform workflow (one-minute answer)
In Terraform, I first write my infrastructure as code in Terraform files. Then I run terraform init to set up the provider. Then terraform plan to preview the changes. Then terraform apply to create the actual resources in AWS. If I want to remove everything, I run terraform destroy.
Ansible architecture (one-minute answer)
In Ansible, the Control Node is where Ansible is installed. It reads the Inventory file to know the Managed Nodes. I write tasks in a Playbook, using Modules. Ansible connects to the Managed Nodes through SSH, and runs the playbook tasks on them, without needing any agent installed.

18 · Troubleshooting scenarios

🔥 must know

For every scenario, follow the same pattern out loud: what you'd check first → the command → the likely reason → the fix. You don't need to know the exact real answer — showing the right approach is what matters for a fresher.

Docker container stopped

FIRST CHECKContainer status
COMMANDdocker ps -a
REASONApplication crashed, wrong config, or missing dependency
FIXCheck docker logs, fix the issue, then docker start
First I check docker ps -a to see the container status. Then I check docker logs to find the error. Based on the reason, I fix the issue and start the container again.

Container running but application not accessible

FIRST CHECKPort mapping, security group
COMMANDdocker ps
REASONWrong port mapping, or firewall blocking the port
FIXFix port mapping, or open the port in the security group
I check if the container port is mapped correctly using docker ps. Then I check the security group or firewall settings, to make sure the port is open.

Jenkins build failed

FIRST CHECKConsole output
REASONCode error, missing dependency, wrong configuration
FIXFix the issue, rerun the build
I check the console output of the failed build. I find the exact error message, fix the issue — like a code error or missing dependency — then I run the build again.

Jenkins cannot clone the GitHub repository

FIRST CHECKRepository URL, credentials
REASONWrong URL, expired token, network issue
FIXUpdate credentials or fix the URL
I check if the repository URL is correct, and if the credentials or SSH key are valid. Sometimes the token expires, so I need to update it.

Git push failed

REASONNo permission, remote has new changes, wrong branch
FIXgit pull first, then push again; check credentials
First I check the error message. If it says the remote has new changes, I run git pull first, then push again. If it's a permission issue, I check my credentials.

Maven build failed

REASONCompilation error, missing dependency, failed test
FIXCheck the build log, fix code or pom.xml, rebuild
I check the Maven build log to see if it's a compilation error, missing dependency, or failed test case, and then fix that issue.

EC2 server not reachable

FIRST CHECKInstance state, security group, key pair
I check if the instance is in running state. Then I check the security group rules, to see if the correct port is open. I also confirm I am using the right key and public IP.

Application is down

FIRST CHECKServer reachable, process running, logs
First I check if the server is reachable. Then I check if the application process is running. Then I check the application logs to find the reason.

CPU usage very high

COMMANDtop
I use the top command to check which process is using high CPU, then decide if I need to restart it or scale the server.

Disk is full

COMMANDdf -h
I use df -h to check disk usage, find which folder is taking space, and clean up unnecessary files or old logs.

Application is slow

FIRST CHECKCPU, memory, logs
I check CPU and memory usage, and application logs, to see if there's a resource issue or an error causing the slowness.

Docker image not found

REASONWrong image name/tag, or image not pushed to registry
I check if the image name and tag are correct, and confirm the image is available in the Docker registry.

Jenkins pipeline failed during the Docker build stage

REASONDockerfile error, missing base image, syntax issue
I check the console output for the Docker build stage, look at the Dockerfile for errors, and fix the issue, like a wrong base image or a syntax mistake.

Jenkins pipeline failed during the Maven build stage

REASONCompilation error or missing dependency in pom.xml
I check the console output for the Maven stage specifically, and look for compilation errors or missing dependencies in pom.xml.
